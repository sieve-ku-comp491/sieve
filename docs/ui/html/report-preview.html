SQL injection in the login form of the SQL injection lab

Severity
Critical CVSS 4.0 score 9.3
Vector
CVSS:4.0/AV:N/AC:L/AT:N/PR:N/UI:N/VC:H/VI:H/VA:N/SC:N/SI:N/SA:N
Location
dockerized_labs/sql_injection_lab/app.py, lines 46 to 57
Repository
github.com/adeyosemanputra/pygoat at 2aa4cc1

Summary

The /lab route of the SQL injection lab builds its login query by formatting the submitted username and password into an SQL string, and runs it with sqlite3's execute() without query parameters.

Impact

An unauthenticated attacker can log in as any user, including admin, without knowing the password, and can read other rows of the users table through the query's result.

Steps to reproduce

  1. Start the SQL injection lab from dockerized_labs/sql_injection_lab.
  2. Open the lab's /lab page.
  3. Enter admin' -- as the username and any password, and submit the form.
  4. The page shows that you are logged in as admin.

Fix

Pass the values as query parameters instead of formatting them into the string:

result = c.execute(
    "SELECT * FROM users WHERE username = ? AND password = ?",
    (username, password),
).fetchone()
